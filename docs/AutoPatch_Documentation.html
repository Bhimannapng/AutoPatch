Part 1: High-Level Overview (In Simple English)

What is AutoPatch in One Sentence?

AutoPatch is like an autonomous, senior software engineering team that you can feed any codebase to—whether it is a full project ZIP, a GitHub link, or a single file—and it immediately maps how the software connects, finds all hidden bugs, optimizes slow code and memory leaks, writes targeted code fixes, and tests those fixes in an isolated sandbox to prove they actually work.

The Real-World Problem It Solves

In modern software development, debugging code is one of the biggest bottlenecks. Developers face three major limitations with existing tools:

1. Conventional Linters Are Blind

Traditional linters (Flake8, ESLint) only spot trivial syntax errors. They cannot detect cross-file logical defects, broken API contracts, or high-complexity algorithms.

2. Generic AI Chatbots Hallucinate

Pasting code into generic chatbots returns speculative, untested code snippets that often break other parts of the project or introduce new security bugs.

3. No Automated Verification

Developers must manually copy, paste, run, and test every proposed fix, wasting hours of engineering time on manual verification loops.

How AutoPatch Solves This (The 4-Pillar Approach)

  • Full-Project Context Understanding: AutoPatch does not look at code in isolation. It understands the entire directory structure, identifies entry points, reads configuration files, and maps dependencies across files.
  • All-in-One Multi-Error Detection: Instead of quitting after encountering the first error, AutoPatch analyzes the complete codebase and reports all detectable syntax, semantic, logic, performance, and security issues in one structured pass.
  • Automated Sandbox Verification: Every suggested code patch is automatically compiled and executed in a sandboxed runtime. The platform verifies whether the patch resolves the issue without introducing regressions.
  • Specialized AI Triad: Instead of a single generic model, three specialized AI agents (Dr. Patch, Nova, and Aegis) inspect the project from different angles (functional correctness, performance, and security).

Detailed Stage Breakdown

Stage 1: Secure Ingestion & Extraction

The user uploads a ZIP archive, inputs a GitHub repository URL, or pastes raw source code. The backend safely extracts the contents with path-traversal prevention (preventing Zip Slip attacks). It normalizes paths, filters out unwanted clutter (e.g., .git, node_modules, __pycache__), and calculates the physical storage overhead.

Stage 2: Architectural Discovery & Entry Point Detection

AutoPatch inspects the file tree to classify languages (Python, JavaScript, HTML, CSS, Java, etc.) and recognize frameworks (FastAPI, Flask, React, Vite). It identifies key application entry points (e.g., main.py, server.py, index.html) and traces cross-file imports to construct a dynamic dependency graph.

Stage 3: Multi-Category LLM Defect Detection

The complete source code and structural context are dispatched to the Google Gemini AI engine with strict schema enforcement. The engine inspects every function, class, loop, variable assignment, and condition to detect:

  • Syntax Errors: Missing colons, unmatched brackets, invalid tokens.
  • Logical & Semantic Bugs: Zero-division risks, mutable default arguments, undefined variables, unreachable code, wrong return types.
  • Frontend Accessibility: Missing image alt tags, missing character encodings, unhandled fetch errors.

Stage 4 & 5: Targeted Patching & Sandbox Verification

For every detected error, AutoPatch synthesizes a targeted code patch (a minimal diff rather than rewriting entire files). The patched snippet is then piped into an isolated Python/AST sandbox where syntax trees are compiled and verified. If the fix passes, the status changes to VERIFIED PASSED.

Stage 6: RAM, CPU & Security Auditing

In parallel with bug detection, the engine evaluates resource efficiency:

  • CPU & Complexity: Identifies $O(N^2)$ and $O(N^3)$ nested loops and suggests refactoring using hash maps or vectorized operations.
  • RAM & Memory Leaks: Flags unclosed file handles (unmanaged open() calls), redundant debug prints, and unbound in-memory list growth.
  • Security (OWASP): Detects hardcoded API keys, unescaped SQL queries, and unsafe script injections.

The Three Specialized AI Agents

Instead of a single one-size-fits-all model, AutoPatch features a Multi-Agent Intelligence Hub where three virtual specialists examine the project:

Dr. Patch
Lead Bug Hunter & Logic Specialist

Specializes in syntax errors, runtime crashes, semantic bugs, type mismatches, and generating minimal surgical code patches.

Nova
Performance & RAM Architect

Analyzes algorithmic complexity ($O(N^2)/O(N^3)$ loops), memory leaks, garbage collection overhead, and stream generator optimizations.

Aegis
Security & Modularity Guardian

Audits code against OWASP vulnerabilities, finds hardcoded API secrets, detects SQL injection patterns, and verifies cross-file import consistency.

Key Engineering Innovations

  • Deterministic Schema Enforcement: The backend uses Pydantic v2 schemas and strict JSON formatting to eliminate hallucinated formatting from LLM outputs.
  • Multi-Error Aggregator: Analyzes all 50+ lines across multiple files in a single pass without stopping at the first failure.
  • One-Click Workspace Reset: A persistent "Delete Project" action safely scrubs temporary extracted files and in-memory analytics, allowing seamless consecutive uploads.
  • Export Patched ZIP: Allows developers to instantly bundle and download the fully repaired codebase with all verified patches applied.
